# Rental settlement backend proof

Plan: `../private-artifacts/backend-proof/PLAN.md`

## Purpose

Build the host/reseller rental backend layer by layer, using Aqua settlement, ERC-1155 property-time rights and testnet USDC. Validate the rights, trading economics and booking lifecycle as well as the infrastructure. Every new layer above the existing PR #8 foundation must become maintained backend code and have its own proven, reviewable PR. Backend-first is an execution order; it does not discard unresolved product mechanisms. UI work is deferred.

## Methodology

- For each layer: state the user-visible promise and invariant; identify the smallest uncertain mechanism; implement it in maintained backend code; run a bounded counterexample test through its real consumer; retain only necessary reproducibility inputs. Record the decision and limitations privately before depending on it.
- Adversarially review and revise each layer PR before advancing to the next publication. Revalidate any corrected dependency in its downstream consumers.
- One proven layer per PR, with atomic commits inside it. A layer is a separately testable capability, not one file or an arbitrary task count. Each PR includes its code, focused tests, necessary schema migration and concise usage/specification changes. Use explicit dependency PRs so each diff contains only its layer. Revalidate after dependency or base changes.
- Preserve the full requirement set. Track each layer separately in production-layers.md and the private closure ledger. An implemented subset, documented limitation, rejected candidate, or green CI badge cannot close an untested consumer or silently remove a product requirement. A disproved promise needs a concrete replacement and its test; consequential commercial choices remain explicit.
- Derive the data model from backend/onchain/VM validation. Treat the existing product plan and UI as preliminary inputs, not constraints on final structures. Keep UI implementation deferred. Preserve unrelated application work.
- Keep plans, methodology, research, temporary experiments, transcripts and full receipts private. Commit maintained code, essential tests, dependency pins, technical documentation and minimal public deployment references. Distinguish local, fork and public-testnet evidence, including which checks CI actually runs.
- Follow repository PR rules, conventional titles, attribution and AI disclosure. Never push to main. The current user authorizes reviewing, improving and merging all open PRs through repository rules; this supersedes the earlier no-merge and PR #8 freeze for necessary reviewed corrections. Preserve history; build new layer PRs on top of that foundation; the completed cleanup force-push exception does not authorize another history rewrite. CI changes belong in a PR explicitly about verification infrastructure.
- Use testnet USDC for public settlement validation; keep signer material outside Git. Use node --import tsx for TypeScript tools. Delegate only independently verifiable work, retain parent acceptance, and serialize shared schema changes. No production deployment, external supplier actions or prize submission is implied.
